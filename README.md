# MSP430FR2433 + MAXM86161 原始数据采集

根据提供的原理图，使用 eUSCI_B0 I²C 配置 MAXM86161，轮询 FIFO，并接收绿光、红外和红光的 **19 位原始光学读数**。这里没有心率或血氧算法，输出值不能直接解释为 BPM 或 SpO₂。

## 引脚与硬件条件

| 原理图网络 | MSP430FR2433 | MAXM86161 | 固件用途 |
| --- | --- | --- | --- |
| SDA | P1.2 / UCB0SDA，封装脚 9 | SDA，脚 1 | I²C 数据 |
| SCL | P1.3 / UCB0SCL，封装脚 10 | SCL，脚 2 | I²C 时钟，约 92.3 kHz |
| MAXEN | P3.0，封装脚 12 | LDO_EN，脚 3 | 高电平使能 |
| MAXEN1 | P1.7，封装脚 6 | 图中左侧模块未使用此网络 | 保持输入，不驱动 |
| UARTTX | P2.6 / UCA1TXD，封装脚 17 | — | 输出数据到蓝牙模块/串口接收端 RX |
| UARTRX | P2.5 / UCA1RXD，封装脚 16 | — | 本固件未使用 |
| INT | P2.2，封装脚 11 | 左侧图没有画出 INTB 到 INT 的连线 | 轮询模式，无需连接 INTB |

- SDA、SCL 必须有外部上拉，可先各用 4.7 kΩ 上拉到 3.3 V；按总线电容调整。两张图没有显示这些上拉，内部弱上拉不作为替代。
- MCU、传感器和串口模块共地。图中 MCU 与 VLED 共用 VCC，电压需同时满足两者：通常使用 **3.3 V**，共同供电范围为 3.0–3.6 V。不要给 MSP430 接 5 V。
- 保留图中的 VLDO/VREF 1 µF 和 VLED 10 µF 去耦。检查 MAXEN 实际通向 P3.0；代码只驱动这一根使能线。
- UART 使用 MCU 电平。连接 USB 串口时，将 P2.6 接适配器 RX；蓝牙模块的 UART 参数也需匹配。

## 采集行为

- I²C 7 位地址为 `0x62`（线上写地址 `0xC4`、读地址 `0xC5`），`0xFF` 的 Part ID 应为 `0x36`。
- 上电后软件复位、等待复位完成，执行数据手册规定的 ADC/DAC 自校准，并校验写入配置。
- LED 序列为绿光、红外、红光；序列寄存器 `0x20=0x21`、`0x21=0x03`、`0x22=0x00`。
- 每通道约 99.902 samples/s，积分时间 117.3 µs、ADC 量程 16 µA。三个 LED 初始脉冲电流约 4.8 mA，后续可按光路、供电和是否饱和调整。
- FIFO 数据寄存器 `0x08` 每条必须连续读 3 字节。高 5 位为序列标签，低 19 位为 ADC 数值；标签 1/2/3 在当前序列下分别对应绿光/红外/红光。
- 完整三通道帧才发布到读数变量。异常标签或溢出会丢弃未完成帧，避免混合不同采样时刻的数据。
- 总线等待、复位和校准都有上限；通信失败会关闭/重启传感器、尝试释放总线，并重新配置。FIFO 满时停止写入，溢出后清 FIFO 并重新同步。
- 使用 REFO + FLL 产生约 1.015808 MHz 的 MCLK/SMCLK。UART 标称 **9600 baud、8 数据位、无校验、1 停止位**，实际约 9583 baud，偏差小于 0.2%。

## 接收读数

串口输出约 10 行/秒，每行是三个十进制整数：

```text
绿光原始值,红外原始值,红光原始值\r\n
```

例如 `101,202,303` 只是格式示例，不是实测结果。传感器仍以约 100 Hz 采样；串口输出的是抽取后的最新完整帧。每通道数值范围为 0–524287。

没有串口连接时，也可在 CCS 的 Expressions 中添加：

| 变量 | 含义 |
| --- | --- |
| `g_ready` | 配置成功为 1；不代表已验证光学信号 |
| `g_part_id` | 成功识别应为 `0x36` |
| `g_green`, `g_ir`, `g_red` | 最新完整帧的三个原始读数 |
| `g_frame_count` | 完整帧数量，应随采集增长 |
| `g_sample_count` | 已接收 FIFO 数据条数 |
| `g_error` | 最近一次操作结果，见下表 |
| `g_clock_error` | FLL 无法锁定时为 1，传感器保持关闭 |
| `g_i2c_errors`, `g_sensor_errors` | 通信错误和初始化/配置错误次数 |
| `g_fifo_overflows`, `g_tag_errors`, `g_uart_errors` | FIFO 溢出、标签不同步和串口发送错误次数 |

| `g_error` 值 | 含义 |
| --- | --- |
| 0 | 成功 |
| 1 | I²C NACK，检查地址、电源、MAXEN、连线 |
| 2 | 等待超时 |
| 3 | 总线占用/被拉低或仲裁丢失，检查上拉和连线 |
| 4 | Part ID 不符 |
| 5 | 软件复位未完成 |
| 6 | 校准未完成 |
| 7 | 校准 DAC 超出范围 |
| 8 | FIFO 溢出，已尝试清 FIFO |
| 9 | 配置寄存器读回不符 |
| 10 | 无效 API 参数 |

MSP430 为 16 位 MCU，32 位调试变量在运行中刷新时可能出现瞬间的不一致；需要一致快照时，在 `accept_sample()` 发布完整帧后设置断点。长时间暂停 CPU 会导致传感器 FIFO 溢出，恢复运行后固件会处理它。

## CCS 构建和板上验证

1. 在 CCS 12.8 中用 **Import CCS Projects** 导入此目录。原工程名称保留为 `test`，目标为 MSP430FR2433，编译器版本为 TI 21.6.1.LTS。
2. 确认工程包含 `main.c`、`board.c`、`maxm86161.c` 和原有 `lnk_msp430fr2433.cmd`。器件头文件、被链接脚本引用的 `msp430fr2433.cmd`、`libc.a` 和 `libmath.a` 来自 CCS 器件支持及编译器安装，不要用普通桌面 GCC 替代。Debug/Release 的栈已增至 512 字节。
3. Build Project 后通过 MSP430 调试器下载，运行。先检查 `g_part_id=0x36`、`g_ready=1` 和 `g_frame_count` 持续增加。
4. 以 9600/8N1 接收 UARTTX。用逻辑分析仪核查地址 C4/C5、ACK、寄存器地址写入后 repeated START，以及每条 FIFO 连续 3 字节读取。
5. 移动手指/遮挡光路，确认读数有对应变化；若持续接近 0 或 524287，检查光路、LED 电源余量、环境光和电流/ADC 量程，而不是把它当作有效生理指标。

## 云端验证及当前限制

在本目录运行：

```sh
python3 tests/test_driver.py
```

该测试以模拟 I²C 总线验证初始化、校准等待、配置读回、失败处理、FIFO 大端解析/容量/溢出、三通道帧同步和 UART CSV 格式，并使用 AddressSanitizer/UndefinedBehaviorSanitizer。它不模拟 MSP430 的 eUSCI 硬件时序，也不验证真实光学数据。

固件已通过上述主机测试，并使用 TI FR2433 寄存器定义做过主机语法检查（CPU intrinsic 使用占位实现）。**尚未完成 TI 目标编译、烧录或板上通信验证**。TI 安装包下载会重定向到 `dr-download-cdn.ti.com`，当前运行环境尚无法下载；网络域名增补已保存到环境配置草稿，需要在环境设置中保存并发布后继续安装验证。
